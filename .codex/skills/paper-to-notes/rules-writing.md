# 通用写作风格约束

## 语言

1. 默认使用中文，除非用户明确指定其他语言。
2. 表达简洁、准确、自然，避免不必要的铺垫和重复。
3. 技术术语首次出现时，必要时补充简短解释。
4. 中文标题和字段名称用词简洁，同级内容保持对称。

## 结构

1. 先给结论，再给必要的说明。
2. 根据内容复杂度使用标题、列表或表格，不为简单内容过度排版。
3. 多个并列项目使用统一的句式和粒度。
4. 用户要求精简时，只保留完成任务所必需的信息。

## 事实与判断

1. 区分原文事实、个人解释、合理推断和工程补充。
2. 不确定的信息明确标注，不凭常识补全缺失内容。
3. 涉及论文时，论文未说明的信息标记为“论文未说明”。
4. 不把推测、建议或经验表述成确定事实。

## 格式

1. Markdown 表格仅用于适合横向比较的内容。
2. 代码、命令、路径和字段名使用反引号；多行代码使用代码块。
3. 文件引用使用可点击的 Markdown 链接。
4. 输出示例应与实际格式一致，避免混用 Markdown 表格和终端边框表格。
5. 有顺序的内容使用 Markdown 默认有序列表，编号必须为阿拉伯数字 `1.`、`2.`、`3.`。
6. 不使用自定义符号代替有序编号；适合拆分的内容优先使用列表表达。

## 交互

1. 需要用户选择时，明确列出当前状态、可选行动和推荐的下一步。
2. 不重复用户已经确认的信息。
3. 执行任务后简要说明修改内容和验证结果。
4. 遇到分号类分隔符时，将前后完整分句分别写成 Markdown `-` 列表项并去掉分隔符，例如：

   ````
   # 原来
   甲；乙
   甲; 乙
   
   # 改为
   - 甲
   - 乙
   ````
5. 最终笔记中不得出现补丁标记、行号、增删号或其他编辑过程痕迹；只保留整理后的正式内容。
6. 原文中的特殊编号统一转换为普通 Markdown 有序列表编号（如 `1.`、`2.`、`3.`），保持原有编号顺序，不额外新增编号。

## Obsidian 笔记属性

1. 每篇最终笔记必须在文件开头使用合法的 YAML Frontmatter，作为 Obsidian 笔记属性；不得把论文元数据只写在正文中。
2. 元数据优先使用以下属性：`title`、`author`、`time` 和 `url`。原文未提供的字段标记为 `Unknown`，不得擅自补全。
3. `title`、`author` 和 `time` 使用字符串属性；发表时间保留论文提供的精度，例如 `2023/07`。
4. `url` 使用链接属性，并保留论文原始 URL。
5. 所有字符串属性值统一使用双引号，不根据字符内容省略引号；这适用于 `title`、`author`、`time`、`url` 以及后续新增的字符串属性。这样可以统一处理冒号、井号、方括号、开头连字符等 YAML 语法字符。例如：

   ```yaml
   ---
   title: "FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning"
   author: "Tri Dao"
   time: "2023/07"
   url: "https://arxiv.org/abs/2307.08691"
   ---
   ```

6. Frontmatter 必须能够被 YAML 正确解析；属性结束后再开始正文内容。

## 图片引用

1. 笔记需要引用来源 Markdown 中的图片时，使用图片的**绝对路径**（源 Markdown 所在目录下的 `images/` 子目录 + 文件名），不要照抄来源中的相对路径，以便后续脚本把图片复制进笔记的 `assets/` 目录。
2. 引用远程图片（`http`/`https`）时保持原样，交由脚本跳过。
3. 无法确认图片来源位置时，宁可省略图片，也不要写入无法解析的相对路径。
