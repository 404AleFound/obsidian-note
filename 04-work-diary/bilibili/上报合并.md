一次时间段内的聚合上报会被塞入大量的手势信息，因此需要进行精简，针对是否为滑动轨迹：
- 非滑动轨迹：只有位置、屏幕长宽、时间戳有用，其余可以丢弃。
- 滑动轨迹：具有除上述信息之外的时长、操作手、需要保留。

```
{"t":"CLICK", "x":0.95, "y":0.39, "wh":874.0, "ww":402.0, "ts":1785949991221}

{"t": "SCROLL", "x":0.91, "y":0.41, "wh":874.0, "ww":402.0, "ts":1785949991221,
"d": "356", "h": "LEFT", "hp": 0.92
}
```

除此之外，还打算对各个手势添加页面类型（详情页、推荐页等等）字段，对滑动手势添加滑动方向字段。

```
{"t":"CLICK", "x":0.95, "y":0.39, "wh":874.0, "ww":402.0, "ts":1785949991221, "p":"PAGE_TYPE"}

{"t": "SCROLL", "x":0.91, "y":0.41, "wh":874.0, "ww":402.0, "ts":1785949991221,
"d": "356", "h":"LEFT", "hp":0.92, "p":"PAGE_TYPE", "dir":"UP"
}
```

但是这样的上报信息仍然冗余，需要对上报信息进行合并，先构思出两种合并思路：
- 思路1：优化 json 字段，合并共同字段，减少上报信息体量。
- 思路2：端上先按屏幕网格分桶聚合，替代逐条 event 上报。

针对合并思路1，并不会减少上报的信息，只是上报形式的改写，针对合并思路2，需要进一步考虑。

对于非滑动手势信息，采取网格分桶上报，相当于将坐标进行离散化，这会损失部分信息；同时也丢失了手势的时序性，合并后的信息如下：

```
{
"wh":874.0,
"ww":402.0,
"p":"PAGE_TYPE",
"ts": 1785949991221,
"dur": 9000,
"gird":0, 
"info":{
	{"t":"CLICK", "amount":43},
	{"t":"LONG_CLICK", "amount":23},
	{"t":"DOUBLE_CLICK", "amount":5},
	{"t":"PINCH_IN", "amount":5},
	{"t":"PINCH_OUT", "amount":5},
	}
}
```

对于滑动手势，如果采取上面的分网格合并，不仅丢失了时序性，也丢失了每个手势的操作手信息的颗粒度也降低了。

```
{

"ww":402.0,
"p":"PAGE_TYPE"
"ts": 1785949991221,
```
