`ScreenActionEvent` 一次屏幕交互的时刻播报，仅仅保留最原始的播报信息。

```kotlin
data class ScreenActionEvent(
	val type: ScreenActionEventType,
	val timestamp: Long,
	val point: TouchPoint,
)
```

>[!note]
>对应的枚举类 `ScreenActionEventType` 定义如下：
>```kotlin
>internal enum class ScreenActionEventType {  
>	UNKNOWN,      // 未知
>	DOWN,         // 手指放下，原始的 MotionEvent    
>	UP,           // 手指抬起，原始的 MotionEvent
>	CANCEL,       // 取消，原始的 MotionEvent    
>	CLICK,        // 点击，来自于 Android Gesture
>	DOUBLE_CLICK, // 双击，来自于 Android Gesture    
>	LONG_CLICK,   // 长按，来自于 Android Gesture
>	SCROLL,       // 滑动，来自于 Android Gesture
>	PINCH_IN,     // 缩放，来Android Gesture    
>	PINCH_OUT,    // 放大，来自于 Android Gesture
>	;
>}
>```

`ScreenActionRecord` 一次屏幕交互的完整记录，有开始结束时刻的记录，并且有手势对应的路径，后续可以记录当前手势在哪种页面进行的操作。

```kotlin
data class ScreenActionRecord(
	val type: ScreenActionRecordType,
	val startTimestamp: Long,
	val endTimestamp: Long,
	val path: List<TouchPoint> = emptyList(),
	// val page 记录当前行为发生的页面
)
```

>[!note]
>对应的枚举类 `ScreenActionRecordType` 定义如下：
>```kotlin
>internal enum class ScreenActionEventType {  
>	UNKNOWN,      // 未知
>	CLICK,        // 点击
>	DOUBLE_CLICK, // 双击
>	LONG_CLICK,   // 长按
>	SCROLL,       // 滑动
>	PINCH_IN,     // 缩放
>	PINCH_OUT,    // 放大
>	BACK,         // 返回
>	;
>}
>```

对于复现用户最近操作的职责，该模块通过返回该数据结构 `List<ScreenActionRecord>` 实现，模块拟提供一个函数接口，供用户调用。

```kotlin
fun queryScreenActions(n: Int = Int.MAX_VALUE): List<ScreenActionRecord> = screenActionQuerier?.invoke(n).orEmpty()
```

> [!question]
或许可以将 20 条快照作为一种状态存储，进行 `stateFlow` 的更新，但是这样可能与直接读缓存相比多了许多无用的拷贝操作，虽然和原始方案更加对齐，但是是否会带来新能上不可避免的开销，有待考证。

依据收集到的 `ScreenActionRecord` 信息，对**短时是否触摸**、**惯用手**、**注意力区域**、**视频观看专注度**等高层信息进行推断。这些高层信息被封装为 `BasicStateEntity` ，通过 `Flow` 输出。

```kotlin
data class BasicStateEntity(
	@PrimaryKey(autoGenerate =true)
	val id: Long = 0,
	val timestamp: Long,
	val name: Int,       // StateField.SCREEN_TOUCH_PRESENCE
	val value: String,   // True or False
```

>[!note]
>对短时有无触摸的枚举类定义如下：
>```kotlin

>	TOUCH,     // 有触摸
>	NO_TOUCH,  // 无触摸
>	;
>}
>```

>
>
